# タスク一覧:難易度とモデル割り当て

全体方針: [ui-improvement-strategy.md](ui-improvement-strategy.md) / 画面別戦略: [screens/README.md](screens/README.md)

## 割り当ての原則

| モデル | 使いどころ | 目安 |
|---|---|---|
| **Haiku 4.5** (`claude-haiku-4-5-20251001`) | 機械的・パターンが確定済みの作業。判断の余地が少なく、見本を渡せば再現できるもの | 難易度 ★ |
| **Sonnet 4.5** (`claude-sonnet-4-5`) | 既存パターンの適用が中心だが、画面固有の判断が少し入るもの | 難易度 ★★ |
| **Sonnet 5** (`claude-sonnet-5`) | 設計判断・UI/UXセンス・複数ファイルにまたがるリファクタが必要なもの | 難易度 ★★★ |
| **Opus 5** (`claude-opus-5`) | 後続すべての品質を決める基盤部品や、最大規模のstate再編。失敗コストが高いもののみ | 難易度 ★★★★ |

原則: **「見本を作る仕事」は上位モデル、「見本を横展開する仕事」は下位モデル。**
Phase 1 と Phase 2 の最初の1画面(ホーム)で上位モデルがパターンを確立し、以降は下位モデルで量産する構成にしてコストを抑える。

## 実行時の運用ルール

1. **順序厳守**: Phase 1 完了前に Phase 2 以降へ着手しない(1-1〜1-3 が全タスクの依存元)。
2. **下位モデルへの発注には見本を添える**: Haiku/Sonnet 4.5 に渡すときは「参照すべき完成画面・部品」と「該当する screens/*.md」を必ず指定する。
3. **1タスク=1ブランチ/1コミット単位**で完結させ、各タスク後に `tsc --noEmit` と `vite build` を通す。
4. 下位モデルの成果物で迷いが出たら、そのタスクだけ1段上のモデルに引き上げる(逆はしない)。
