# UI/UX 改善方針・戦略

作成日: 2026-07-25
対象: KAKEIBO(モバイル向け家計簿アプリ)
前提: [現状分析](#付録現状分析の要約)で特定した3つの構造的問題を解消する。細部の画面仕様は本書では扱わない(フェーズごとに別途詳細化する)。
画面ごとの詳細戦略: [screens/README.md](screens/README.md)

---

## 1. ゴール

**「開いて3秒で今月の状況が分かり、片手で操作できる家計簿」にする。**

- 現状把握・分析が**読む**作業ではなく**見る**だけで済む
- モバイル実機で快適に読める・触れる
- どの画面を開いても同じアプリだと感じる一貫したトンマナ

## 2. 基本原則(すべての改善判断の基準)

### 原則1: 1画面1メッセージ
各画面が答える質問をひとつに絞る。

| 画面 | 答えるべき質問 |
|---|---|
| ホーム | 今月、あといくら残せる? |
| 支出 | 今月いくら使う見込み? |
| 予算 | どのカテゴリが危ない? |
| レポート | 先月までと比べてどう? |

その質問への答え(=ヒーロー要素)を最上部に大きく置き、それ以外の情報は「要約 → タップで詳細」の2階層に落とす。**詳細を消すのではなく、初期表示から追い出す**のが方針。統計値(標準偏差・信頼区間など)や長い説明文は詳細階層へ。

### 原則2: 文字より図、フル桁より要約
- 状況把握の主役をプログレスバー・チャートに置き換える。現状の2pxバーは「装飾」であり、**8px以上の太さ・色で状態が読めるバー**、カテゴリ内訳はドーナツまたは横棒、推移はしっかりした棒グラフ/スパークラインに格上げする。
- カテゴリに**色とアイコン**を割り当て、リストを見た目で識別できるようにする。
- 金額はコンテキストで使い分ける:ヒーローや一覧は「12.3万」等の要約表記、編集・明細ではフル桁。

### 原則3: デザインシステムで一貫性を強制する
トンマナの不統一は「決め事がない」ことより「決め事を守る仕組みがない」ことが原因(インラインstyle約150箇所)。**個別画面の修正より先に、共有の仕組みを作る。**

1. **タイポスケールの固定**: 12段階 → 5〜6段階に削減。本文の最小を13px以上、補助テキストは12pxを下限にする。
2. **スペーシングスケール**: 4pxグリッド(4/8/12/16/24/32)に統一。
3. **色のセマンティクス定義**: green=良い状態・達成、red=超過・警告のみ、amber=注意、primary=操作・選択。金額そのものに警告色を使わない。カテゴリ色は別パレットとして追加。
4. **共有コンポーネント化**: ScreenHeader / Hero / StatCard / CategoryRow / Chart 系を common に集約し、**画面コンポーネントからインラインstyleを原則排除**する。

### 原則4: 閲覧と編集の分離
リスト行の常時編集input(予算・支出・習慣)をやめ、閲覧行はタップ→編集シート(ボトムシート)を開く方式に統一する。これにより:
- 閲覧時の視覚ノイズと誤タップが消える
- タップターゲットを行全体(44px以上)にできる
- 追加フォーム・編集フォームのUIを1つに統一できる

### 原則5: 言葉とナビの整合
- 画面タイトル=ナビラベルに統一(「支出予測」→「支出」等)。
- ボタン文言・単位表記・記号のスタイルガイドを1枚定め、揺れ(登録/追加、円/月 等)をなくす。
- ドロワー内の雑多な5画面は役割で再編する(分析系: レポート/年間、計画系: 投資/習慣、設定系: 給与/目標)。

## 3. 何を変えないか(スコープ外)

- 機能・計算ロジック(`lib/calc.ts`, `useComputed.ts` の算出内容)は原則維持。表示の仕方だけを変える。
- データモデル・Supabase 連携は変更しない。
- ダーク基調のトーン自体は維持(Quiet Instrument トークンを土台に拡張)。ライトテーマ対応は本戦略の後の検討課題。

## 4. 進め方(フェーズ戦略)

依存関係の順に4フェーズ。**Phase 1 を飛ばして画面をいじり始めない**こと(不統一の再生産になるため)。

### Phase 1: 基盤 — デザインシステム整備
- タイポ・スペーシング・色セマンティクスのトークン化(CSS変数)
- 共有コンポーネント群の新設(ScreenHeader / Hero / 太いProgressBar / StatCard / 編集ボトムシート / チャート基礎)
- 文言スタイルガイド(用語表・単位・記号)
- 成果物: 画面はまだ変わらないが、以後の画面改修が「部品を並べるだけ」になる状態

### Phase 2: 主要4画面の再構成(ホーム → 支出 → 予算 → レポート)
- 各画面を「1画面1メッセージ+2階層」に再設計し、Phase 1 の部品で組み直す
- チャート導入(内訳ドーナツ/推移グラフ/予算バー)
- 閲覧・編集分離の適用
- 利用頻度が最も高いホームから着手し、1画面ずつ完結させる

### Phase 3: 残り画面の追従(習慣・年間・投資・給与・設定系)
- 同じ部品・same パターンを適用。給与画面の節税系は詳細階層へ整理
- ナビ・メニューの再編と用語統一の総仕上げ

### Phase 4: 磨き込み
- 実機での可読性・タップ領域の総点検(44px監査)
- モーション・トランジション(シート開閉、数値変化)の最小限の追加
- 不要になった旧CSS・インラインstyleの掃除

## 5. 完了判定(Definition of Done)

- [ ] 画面コンポーネントにインラインstyleがほぼ残っていない(レイアウト微調整の数箇所を除く)
- [ ] 本文テキスト13px未満が補助情報以外に存在しない
- [ ] 全画面がファーストビュー内で「その画面の答え」を1つ提示している
- [ ] 各画面にチャートまたは色付きビジュアルが最低1つあり、数字を読まずに状態が分かる
- [ ] 画面タイトルとナビラベルが完全一致
- [ ] タップ可能要素がすべて44px以上
- [ ] 削除・編集などの操作が全画面で同じUIパターン

## 付録:現状分析の要約

1. **情報量過多**: 全10画面が「数字+テキスト+ヘアラインリスト」のみで構成。1画面に最大7ブロック。統計用語(標準偏差、80%信頼区間)が生で露出。
2. **文字文字しさ**: フォントサイズ12段階が乱立し大半が10〜13px。ビジュアル要素は2pxバーと小さな棒グラフ1つのみ。金額は常にフル桁。
3. **トンマナ不統一**: インラインstyle約150箇所でスタイルの一貫性を担保する仕組みがない。ヘッダー3方式、色の意味が未定義(redが警告でない金額に使用等)、画面タイトルとナビラベルが全て不一致、ボタン文言の揺れ。
4. **操作性**: リスト行が常時編集inputで閲覧と編集が未分離。11pxのリンク・削除ボタンなど44px未満のタップターゲット多数。
