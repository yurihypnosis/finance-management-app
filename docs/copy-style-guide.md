## 2. ボタン・操作文言の統一

現状の混在:
- フォームを開くトリガー: 「＋ カテゴリを追加」「＋ イベントを追加」(追加系) / 「＋ 資金移動を登録」「＋ 現金支出を登録」「＋ パターンを登録」「＋ 習慣を登録」(登録系)
- フォーム送信ボタン: `FormActions` 共通コンポーネントにより既に「登録する」/「やめる」で統一済み。
- 削除: `ConfirmDelete` 共通コンポーネントにより「削除」→二度押しで「本当に削除？」に統一済み。

**決定**:
1. フォームを開くトリガー文言は **「＋ 〇〇を追加」に統一**する(「登録」ではなく「追加」)。対象: 「＋ 資金移動を追加」「＋ 現金支出を追加」「＋ パターンを追加」「＋ 習慣を追加」に変更。「＋ カテゴリを追加」「＋ イベントを追加」は変更不要。
2. フォーム送信ボタンは現状の共通コンポーネント `FormActions` の既定値「登録する」/「やめる」を維持する(変更しない)。
3. 削除確認は現状の `ConfirmDelete` の「削除」→「本当に削除？」を維持する(変更しない)。
4. 「〇〇を登録」という言い回しは、フォームを開く前の見出し(例: 「資金移動を登録」)にも使われているが、これも「〇〇を追加」に統一する。

**理由**: ユーザー操作としては「一覧に項目を増やす」という一貫した行為であり、UIの外側(トリガー)は「追加」、内側(実際にデータを確定させる行為)は「登録する」と役割で使い分けるほうが、既存の共通コンポーネント(`FormActions`/`ConfirmDelete`)を変更せず最小の修正で統一できる。「登録」という言葉自体を残す先(送信ボタン・固定支出パターンの「今月に登録」等、実績を確定させる操作)と、「追加」を残す先(フォームを開く導線)を役割で切り分けることで、文言が意味を持つようにする。

**現状からの主な変更点**:
- `Expense.tsx`: 「＋ 資金移動を登録」→「＋ 資金移動を追加」、見出し「資金移動を登録」→「資金移動を追加」。「＋ 現金支出を登録」→「＋ 現金支出を追加」、見出し同様。「＋ パターンを登録」→「＋ パターンを追加」、見出し「固定支出パターンを登録」→「固定支出パターンを追加」。
- `Habit.tsx`: 「＋ 習慣を登録」→「＋ 習慣を追加」、見出し「習慣を登録」→「習慣を追加」。
- `Expense.tsx` の「今月分を◯件まとめて登録」「＋ 今月に登録」「今月分 登録済み」は**変更しない**(これは既存の固定パターンから当月の実績を確定させる操作であり、「追加」ではなく「登録」が意味的に正しい)。
- `Budget.tsx`(「＋ カテゴリを追加」「＋ イベントを追加」)は変更なし。

## 3. 単位・数値表記

**決定**:
1. **フル桁円表記**: `1,234円` の形式(3桁区切りカンマ + 「円」)。編集フォーム・明細行・合計値など「正確な金額を確認する場面」で使用。現状の `fmt()` ヘルパーの出力形式を維持。
2. **万円要約表記**: `12.3万円`(小数第1位 + 「万円」)。ヒーロー要素・見出し直下の大きい数字など「ぱっと見の規模感を伝える場面」で使用。ラベル部分は本文と別の小さいフォントサイズにしてよい(現状の `Home.tsx` の実装パターンを踏襲)。
3. **「万」単独表記の廃止**: `useComputed.ts` の `manYen()` や `Budget.tsx` のイベント表示が現在「12.3万」のように「円」を省略している箇所があるが、単位はどのコンテキストでも省略しない。**「万円」まで書く**ことに統一する(「万」だけで終える表記は廃止)。
4. **「円/月」表記の統一**: 月あたりの金額は「円/月」ではなく **「円/月」は使わず「月◯◯円」または「◯◯円(月)」ではなく、常に文末に「/月」を付ける形 `◯◯円/月` に統一**する。現状 `useComputed.ts` の一部が「月」を先頭に置く表記(`'月' + fmt(hb.month) + '円'`)と混在しているため、「金額円/月」の語順に揃える。
5. **パーセント表記**: 半角数字 + 半角 `%`(`80%`)。小数点は四捨五入して整数表示を基本とする(現状の `Math.round(...) + '%'` パターンを踏襲)。小数第1位まで見せたい特殊なケース(利率など)のみ例外として小数を許容する。

**理由**: フル桁/要約の使い分けは既に `ui-improvement-strategy.md` 原則2で方針決定済み(「ヒーローや一覧は要約、編集・明細ではフル桁」)。本書ではその適用ルールを単位表記のレベルまで落とし込み、「万」単独表記や「月◯◯円」のような語順違いが読み手の理解コストを上げないようにする。

**現状からの主な変更点**:
- `useComputed.ts` の `manYen()` が返す `'12.3万'` に「円」を付加して `'12.3万円'` にする(呼び出し側の表示テンプレートで「万」を重ねて書いている箇所がないか要確認)。
- `Budget.tsx` イベント表示の `(ev.saved / 10000).toFixed(1) + ' / ' + (ev.target / 10000).toFixed(0) + '万'` のような「万」止め表記に「円」を付加。
- `useComputed.ts` の習慣ノート `hb.freq + '・月' + fmt(hb.month) + '円'` を `hb.freq + '・' + fmt(hb.month) + '円/月'` の語順に変更。

## 4. 記号

**決定**:
1. **プラス記号**: ボタン・操作トリガーの先頭(「追加する」を表す記号)は**全角「＋」**で統一(既存の `btn-add` パターンを踏襲)。金額の増減を表す符号(明細の注記など、文中に埋め込む数式的な符号)は**半角「+」「-」**で統一する。両者は役割が異なるため字幅を使い分けてよいが、同一カテゴリ内(操作 or 数値)では混在させない。
2. **矢印**: 画面遷移・詳細誘導を示す文末の矢印は半角「→」で統一(現状の `Home.tsx` 「削減プランを見る →」、`Report.tsx` 「前月比(◯月 →)」のパターンを踏襲)。
3. **中黒「・」**: 同一行内で短い情報を並列に列挙する区切りとして使用する(例: 「毎月定額・週末の駐車料金」「活用度: 低・利用月のみの契約も検討」)。文と文をつなぐ接続詞の代わりには使わない(読点「、」または句点で区切る)。中黒の前後にスペースは入れない。

**理由**: 全角/半角の使い分けが無秩序だと同じ記号でも意味が拾いにくくなる。「操作を表す記号は全角で目立たせる」「数値の符号は半角で数字と一体に見せる」という役割ベースの基準にすることで、揺れを個別修正ではなくルールとして残せる。

**現状からの主な変更点**:
- `Expense.tsx` の資金移動/現金支出の注記(`'資金移動 -' + ...`, `'現金支出 +' + ...`)は既に半角符号でルールに合致しており変更不要。
- `btn-add` 系のトリガー文言は既に全角「＋」で統一されており変更不要。今後増える追加ボタンもこのルールを踏襲する。

## 5. トーン

**決定**:
1. **説明文(`screen-sub`・注記・ヘルプテキスト)は体言止めを基本とせず、「です・ます」調の簡潔な文で統一**する。ただし1行に収まる短いラベル・注記(「明細から自動集計」等)は体言止めのままでよい。文末が動詞で終わる長めの説明文(1文20字を超えるもの)は「〜します」「〜されます」で終える。
2. **統計用語は生の専門用語を出さず、意味を平易な言葉に言い換える。**

| 元の用語 | 言い換え |
|---|---|
| 標準偏差 | ばらつき |
| 80%信頼区間 | 「いつもの月なら◯円〜◯円」 |
| 中心値 | 「だいたいの目安」または「中央の見積もり」 |
| 統計的な年間支出予想 | 「年間の支出見込み」 |

用語自体を完全に削除するのではなく、初期表示は言い換え語を使い、詳細階層(原則1でいう「タップで詳細」)でのみ元の統計用語をカッコ書きで併記してよい(例: 「いつもの月なら28万円〜35万円(統計的には80%信頼区間)」)。

**理由**: `ui-improvement-strategy.md` 原則1が「統計値や長い説明文は詳細階層へ」と定めているが、詳細階層に出す場合でも専門用語をそのまま出すと理解コストが高い。数字の意味を日常語に翻訳してから、必要な人だけが元の統計用語にアクセスできる二段構えにする。

**現状からの主な変更点**:
- `Annual.tsx` の「統計的な年間支出予想(80%信頼区間)」「年間の標準偏差 ±◯◯円」→「いつもの年なら◯◯円〜◯◯円」+ 詳細に「(統計的には80%信頼区間、ばらつき±◯◯円)」を併記。
- `Report.tsx` の「標準偏差」ラベル・「統計的な年間支出予想(80%信頼区間)」も同様に言い換え、元の用語は詳細表示側にのみ残す。
- 体言止め箇所(例: `Salary.tsx` の「* 扶養なし・40歳未満(介護保険料なし)の概算。住民税は賞与からは源泉徴収されない前提です」)は既に「です・ます」で終わっており、この基準の模範例として維持する。
